# JEV Tank Battle

[English](README.md) | **简体中文**

使用原生 JavaScript 和 HTML Canvas 构建的浏览器坦克游戏。你可以通过键盘或触屏操作坦克，在可破坏的墙体之间与 AI 对战。双方每局以三格生命值开始，比分跨局累计。

对手结合了 **Jev 战略决策**与**本地实时战斗控制器**：Jev 选择整体策略，浏览器端负责移动、瞄准、射击和闪避。远程服务不可用时，游戏仍可依靠本地 AI 运行。

## 快速开始

前端没有第三方包依赖，也不需要构建。在项目目录下使用 Python 3 启动静态服务器：

```sh
python3 -m http.server 8000
```

打开 [localhost:8000](http://localhost:8000)。此方式仅提供前端静态文件，无法处理 `/api/jev` 请求，因此游戏会自动使用本地 AI。

也可以在支持 JavaScript 的浏览器中直接打开 `index.html`，但需要保留相邻的 `css/` 和 `js/` 目录。部分移动端文件预览器不会执行 JavaScript，此时请通过浏览器访问已托管的页面。

### 启用 Jev

将前端静态文件和 `api/jev.js` 一起部署到支持其 Vercel 风格请求/响应处理函数的服务端环境，并配置以下环境变量：

| 变量 | 用途 |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | 发起模型请求所使用的 Cloudflare 账号 |
| `CLOUDFLARE_API_TOKEN` | 具有模型调用权限的 API Token |

浏览器通过 `POST /api/jev` 发送游戏状态。服务端使用 `typesafe/jev` 模型调用 Cloudflare AI 接口，并返回结果。凭证仅保留在服务端。

服务端还提供两个诊断入口：

- `GET /api/jev`：检查所需环境变量是否已配置，不会暴露变量值。
- `GET /api/jev?test=1`：实际发起一次模型请求，检查连通性和访问权限。

## AI 策略

当前实际运行的 AI 由 `js/ai.js` 和 `js/ai-killer.js` 中的覆盖实现共同组成。后者在游戏启动前替换基础版本的射击、瞄准、战术候选点生成、位置评分、压制射击和战斗控制函数。

### 1. Jev 战略决策

浏览器汇总战场尺寸、双方位置与生命值、玩家速度、相对几何关系、视线、来弹危险、当前策略及最多 14 个墙体的信息。Jev 根据这份状态快照选择策略：

| 策略 | 目标 |
| --- | --- |
| `ATTACK` | 利用射击机会，持续施加攻击压力 |
| `CHASE` | 缩短距离，改善攻击位置 |
| `FLANK` | 寻找射击通道或截断玩家路线 |
| `EVADE` | 应对迫近的来弹威胁 |
| `RETREAT` | 生存受到威胁时拉开距离 |

模型指令倾向于在存在可靠击杀机会时选择攻击或追击。前端每隔 2.4 秒游戏时间检查是否需要请求决策；如果已有请求正在执行、处于重试退避期，或当前策略仍在保持期内，则跳过请求。成功决策的保持期为 2.8 秒，高危险状态可在下一次检查时绕过保持期，因此实际请求频率可能低于检查频率。

虽然服务端同时向 Jev 询问移动、开火和危险程度，**当前前端只使用返回的策略选择、置信度和模型名称**。即时动作由本地代码决定，本地逻辑也可以覆盖模型选择的策略。

### 2. 本地战斗优先级

战术控制器大约每隔 100 毫秒游戏时间运行一次。每次更新都会估算玩家速度、调整难度、评估攻击机会，并按以下优先级行动：

1. **优质射击机会先开火再闪避。** 当拦截射击质量超过 0.78 且武器冷却完成时，立即开火。
2. **躲避迫近的子弹。** 当威胁距离最近接近时刻不足 0.48 秒，且存在可用的闪避方向时，侧移避开弹道。
3. **向预判拦截点射击。** 存在有效射击解时开火，然后沿当前路径移动；如果玩家距离不足 95 像素，则尝试拉开距离。
4. **压制射击。** 在攻击、追击或击杀模式下，向大致对齐的玩家预测位置开火，让子弹破坏中间的墙体。
5. **调整位置。** 规划并沿路径前往战术位置。如果移动状态为 `STOP` 且玩家距离超过 90 像素，则尝试沿可通行方向逼近玩家。

即使远程决策尚未返回，本地控制器也能持续响应即时战况。

### 3. 预测、选位与寻路

玩家速度通过连续观测进行平滑估计。拦截瞄准会评估四个射击方向，并进行两轮飞行时间修正，估算子弹到达时玩家所在的位置。位于炮口后方、超出横向误差容限或被墙体遮挡的射击解会被排除。

战术候选点包括玩家预测位置周围的水平和垂直射击位、玩家移动方向前方的位置、用于封锁逃跑路线的侧向位置，以及 AI 附近的脱困点。候选列表最多保留 26 个位置。

位置评分优先奖励无遮挡且与玩家对齐的射击通道。理想交战距离约为 165 像素，玩家只剩一格生命值时缩短到 125 像素。不同策略还会调整掩体、侧翼对齐或拉开距离的奖励。

移动采用基于 40 像素网格的广度优先搜索（BFS），最多扩展 500 个节点。正常重新规划的冷却时间为 0.75 秒；击杀模式会将剩余计时缩短到最多 0.18 秒。脱困检测大约每 550 毫秒检查一次移动情况，坦克持续卡住时会清空旧路径，并选择通行空间更大的方向。

### 4. 击杀模式与自适应难度

满足以下任一条件时进入击杀模式：

- 玩家生命值不超过一格。
- AI 生命值高于玩家，且双方距离不足 260 像素。
- 在战术更新中，估算的玩家速度持续低于每秒 18 像素，累计超过 1.1 秒。

如果已记录的危险评分低于 0.78，击杀模式会强制选择 `ATTACK`。它还会加快路径重新规划，并允许持续压制射击。

难度随玩家的领先比分提高，最多按领先四分计算：

| 参数 | 玩家 | AI：玩家未领先 → 玩家领先四分 |
| --- | --- | --- |
| 移动速度 | 145 像素/秒 | 198 → 230 像素/秒 |
| 射击冷却 | 0.42 秒 | 0.18 → 0.132 秒 |
| 子弹速度 | 330 像素/秒 | 420 → 480 像素/秒 |
| 子弹半径 | 4 像素 | 6 → 7.4 像素 |

AI 在这些机制参数上被有意设置得更强。难度调整采用固定的比分规则，本地控制器不会在回合之间进行训练或学习。

### 5. 回退与异常恢复

Jev 请求失败后，如果本地危险评分超过 0.55，浏览器选择 `EVADE`，否则选择 `CHASE`，并设置 1.5 秒的策略保持期。本地战斗控制器继续运行，仍然可以触发击杀模式。503 错误会触发 30 秒重试退避；服务端会在六秒后中止尚未完成的上游模型请求。

帧循环分别捕获逻辑异常和渲染异常，并继续调度后续帧。发生逻辑异常后，会清空 AI 路径并停止其移动，让后续更新有机会恢复。

### 如何理解决策面板

面板同时展示远程决策和本地计算信息：

- **策略置信度（Strategy confidence）** 来自上一次成功的 Jev 响应，或初始默认值。本地逻辑覆盖策略时不会重新计算置信度。
- **移动条形图（Movement）** 使用固定权重展示当前方向：选中方向为 84%，其余每个方向为 4%。
- **开火指标（Fire）** 是本地启发式指标，并非经过校准的命中概率，也不是随机开火阈值。
- **危险程度（Danger）** 来自本地来弹分析。
- **决策次数和日志（Decision count / log）** 记录成功的 Jev 决策；初始化时也会添加日志条目。

## 项目结构

| 文件 | 职责 |
| --- | --- |
| `index.html` | 页面结构与有序资源加载 |
| `css/style.css` | 桌面与移动端样式 |
| `js/state.js` | 共享状态、常量、工具函数与画布尺寸设置 |
| `js/game.js` | 坦克、墙体、碰撞、移动、子弹、回合与生命值 HUD |
| `js/ai.js` | 基础感知、预测、闪避、寻路、战术与脱困 |
| `js/jev.js` | 状态序列化、Jev 请求、响应解析与回退 |
| `js/ui.js` | 决策面板、日志、键盘与触屏输入 |
| `js/render.js` | 画布绘制与粒子更新 |
| `js/loop.js` | 游戏更新、渲染调度与帧异常恢复 |
| `js/ai-killer.js` | 实际生效的强化战斗覆盖实现与自适应难度 |
| `js/main.js` | 初始回合设置与循环启动 |
| `api/jev.js` | 服务端 Jev 代理与诊断接口 |
| `tests/smoke.cjs` | 确定性模拟测试与可选的原版对比 |

脚本使用普通 `defer` 标签，共享顶层作用域。请保留 `index.html` 中的顺序：共享状态最先加载，基础函数在 AI 覆盖实现之前加载，`main.js` 最后执行。如果要改为 `async`、ES 模块或独立 IIFE，需要显式重构依赖和状态管理。

## 验证

使用 Node.js 运行冒烟测试，无需安装测试依赖：

```sh
node tests/smoke.cjs
```

测试分别在接口成功、HTTP 503 和网络失败三种场景下模拟 900 帧，覆盖移动、射击、输入释放、回合重开和本地回退，并检查是否出现逻辑或渲染异常。

如果保存了原始单文件版本，可以运行对比测试：

```sh
node tests/smoke.cjs /path/to/original-index.html
```

对比模式会额外逐帧检查游戏状态、界面更新和请求内容是否一致。测试使用模拟 DOM 和画布；视觉布局和真实浏览器输入仍需在浏览器中验证。
